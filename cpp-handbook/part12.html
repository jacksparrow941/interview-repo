Coding Interview Strategy

Every coding problem follows the same pattern. Master the pattern, then apply it to any problem.

  1. Clarify (2 min): edge cases, input range, constraints, expected output format.
  2. Examples (1 min): trace through 1-2 examples on paper. Catch misunderstanding early.
  3. Brute Force (1 min): state it, explain complexity, don't code it (unless asked). Show you understand the baseline.
  4. Optimize (5 min): identify bottleneck (sort? unnecessary recomputation? wrong data structure?). Think about patterns.
  5. Code (10 min): clean, readable, handle edge cases inline while coding.
  6. Test (3 min): trace your solution on your own examples. Check edge cases: empty, single element, all same.

#1Two SumEasy⏱ O(n)  |  🗄 O(n)

Given an array of integers and a target, return indices of two numbers that add to target. Assume exactly one solution exists.

🧠 Key Insight: HashMap lookup is O(1) average. The key insight: instead of 'find b such that a+b=target', reframe as 'for each a, lookup (target-a) in constant time'.
🔴 Brute Force
// O(n^2): check all pairs
for(int i=0;i<n;++i)
  for(int j=i+1;j<n;++j)
    if(nums[i]+nums[j]==target)
      return {i,j};
// Problem: 10^4 elements = 10^8 operations → TLE
🟡 Better
// O(n log n): sort + two pointers
// Problem: sorting loses original indices
// Need extra array to track original positions
🟢 Optimal
// O(n): HashMap stores value→index
unordered_map<int,int> seen;
for(int i=0;i<n;++i){
  int need=target-nums[i];
  if(seen.count(need)) return {seen[need],i};
  seen[nums[i]]=i;
}
// Key insight: complement lookup replaces nested loop
#2Maximum Subarray (Kadane's Algorithm)Medium⏱ O(n)  |  🗄 O(1)

Find the contiguous subarray with the largest sum. Array may have negative numbers.

🧠 Key Insight: Kadane's insight: at each position, the best subarray ending here is either just nums[i] (start fresh) or extend the previous best subarray. This local decision is optimal.
🔴 Brute Force
// O(n^2): try all start/end pairs
int best=INT_MIN;
for(int i=0;i<n;++i){
  int sum=0;
  for(int j=i;j<n;++j){
    sum+=nums[j];
    best=max(best,sum);
  }
}
return best;
🟡 Better
// O(n) with O(n) space: precompute prefix sums
vector<int> pre(n+1,0);
for(int i=0;i<n;++i) pre[i+1]=pre[i]+nums[i];
int best=INT_MIN;
for(int i=0;i<n;++i)
  for(int j=i;j<n;++j)
    best=max(best,pre[j+1]-pre[i]);
return best;
🟢 Optimal
// O(n) time O(1) space: Kadane's
// Key: cur = max subarray ending at i
// Either extend previous or start fresh at i
int cur=nums[0],best=nums[0];
for(int i=1;i<n;++i){
  cur=max(nums[i],cur+nums[i]);
  best=max(best,cur);
}
return best;
#3Trapping Rain WaterHard⏱ O(n)  |  🗄 O(1)

Given n non-negative integers representing elevation heights, compute how much water it can trap after raining.

🧠 Key Insight: Two-pointer insight: if h[lo] < h[hi], the water at lo is determined by maxLeft (not maxRight, because there's a taller wall on the right). Process the shorter side first.
🔴 Brute Force
// O(n^2): for each position find maxL and maxR
int total=0;
for(int i=1;i<n-1;++i){
  int maxL=*max_element(h,h+i);
  int maxR=*max_element(h+i+1,h+n);
  total+=max(0,min(maxL,maxR)-h[i]);
}
return total;
🟡 Better
// O(n) time O(n) space: precompute maxL[] maxR[]
vector<int> L(n),R(n);
L[0]=h[0];
for(int i=1;i<n;++i) L[i]=max(L[i-1],h[i]);
R[n-1]=h[n-1];
for(int i=n-2;i>=0;--i) R[i]=max(R[i+1],h[i]);
int w=0;
for(int i=0;i<n;++i) w+=max(0,min(L[i],R[i])-h[i]);
return w;
🟢 Optimal
// O(n) time O(1) space: two pointers
int lo=0,hi=n-1,ml=0,mr=0,w=0;
while(lo<hi){
  if(h[lo]<h[hi]){
    ml=max(ml,h[lo]);
    w+=ml-h[lo++];  // min(ml,mr)=ml since h[lo]<h[hi]
  }else{
    mr=max(mr,h[hi]);
    w+=mr-h[hi--];
  }
}
return w;
#4Longest Substring Without RepeatingMedium⏱ O(n)  |  🗄 O(min(n,alphabet))

Find length of longest substring without repeating characters.

🧠 Key Insight: Sliding window: expand hi always, contract lo only when duplicate found. Key: jump lo past the PREVIOUS occurrence, but only if it's within current window (max(lo, prev+1)).
🔴 Brute Force
// O(n^3): check all substrings for uniqueness
int best=0;
for(int i=0;i<n;++i)
  for(int j=i;j<n;++j)
    if(all_unique(s,i,j)) best=max(best,j-i+1);
return best;
🟡 Better
// O(n^2): expand from each position, stop on repeat
for(int i=0;i<n;++i){
  set<char> seen;
  for(int j=i;j<n;++j){
    if(seen.count(s[j])) break;
    seen.insert(s[j]);
    best=max(best,j-i+1);
  }
}
🟢 Optimal
// O(n): sliding window with HashMap
unordered_map<char,int> last;
int lo=0,best=0;
for(int hi=0;hi<n;++hi){
  if(last.count(s[hi]))
    lo=max(lo,last[s[hi]]+1); // jump past duplicate
  last[s[hi]]=hi;
  best=max(best,hi-lo+1);
}
return best;
#5LRU CacheMedium⏱ O(1) get and put  |  🗄 O(capacity)

Design a data structure supporting get(key) and put(key,val) with LRU eviction when at capacity.

🧠 Key Insight: The list iterator (pointer) stored in the HashMap is the key. std::list::splice relinks nodes in O(1) — no data movement. This is exactly how Linux kernel's page cache LRU works.
🔴 Brute Force
// Array: O(n) per operation — scan to find LRU
vector<pair<int,int>> cache; // [key,val] in LRU order
// get: linear scan to find key, move to back O(n)
// put: linear scan, evict front O(n)
🟡 Better
// HashMap + sorted container: O(log n)
map<int, pair<int,int>> ordered; // timestamp → (key,val)
// get/put: O(log n) for map operations
🟢 Optimal
// HashMap + Doubly-Linked List: O(1)
list<pair<int,int>> lst;   // {key,val}, MRU at front
unordered_map<int,list<pair<int,int>>::iterator> mp;
int get(int k){
  if(!mp.count(k)) return -1;
  lst.splice(lst.begin(),lst,mp[k]); // move to front O(1)
  return mp[k]->second;
}
void put(int k,int v){
  if(mp.count(k)){mp[k]->second=v;lst.splice(lst.begin(),lst,mp[k]);return;}
  if((int)lst.size()==cap){mp.erase(lst.back().first);lst.pop_back();}
  lst.emplace_front(k,v);mp[k]=lst.begin();
}
#6Merge K Sorted ListsHard⏱ O(N log k)  |  🗄 O(k)

Given k sorted linked lists, merge them into one sorted list. N = total nodes.

🧠 Key Insight: The heap always gives the globally minimum unmerged element in O(log k). Only the current frontier (k elements) is in the heap at once — space is O(k), not O(N).
🔴 Brute Force
// O(Nk): sequentially merge lists one by one
ListNode* merge_two(ListNode* a, ListNode* b){...}
ListNode* res=lists[0];
for(int i=1;i<k;++i)
  res=merge_two(res,lists[i]); // each merge: O(N) for k passes = O(Nk)
🟡 Better
// O(N log k) but more complex: divide and conquer
// Recursively merge pairs: round 1: k/2 merges, round 2: k/4, etc.
// log(k) rounds × O(N) each = O(N log k)
// Same complexity as heap, more code
🟢 Optimal
// O(N log k): min-heap of (value, node*) 
priority_queue<T,vector<T>,greater<>> pq;
for(auto* h:lists) if(h) pq.push({h->val,h});
ListNode dummy,*tail=&dummy;
while(!pq.empty()){
  auto[v,node]=pq.top();pq.pop();
  tail->next=node;tail=tail->next;
  if(node->next) pq.push({node->next->val,node->next});
}
return dummy.next;
#7Binary Tree Maximum Path SumHard⏱ O(n)  |  🗄 O(h)

Find the maximum path sum in a binary tree. A path can start and end at any node.

🧠 Key Insight: Key insight: path through a node can use both children, but when returning to parent, we can only extend in ONE direction (you can't go down both children and then back up).
🔴 Brute Force
// Try all pairs of nodes: O(n^2)
// For each node, compute longest path through it
// Naive: recompute heights repeatedly
🟡 Better
// Store heights in map: O(n) but O(n) space and complex code
🟢 Optimal
// O(n): DFS, track global max, return max gain upward
int ans=INT_MIN;
int dfs(TreeNode* n){
  if(!n) return 0;
  // Only take positive gains from children
  int L=max(0,dfs(n->left));
  int R=max(0,dfs(n->right));
  // Path through n: L + n->val + R (can't go up)
  ans=max(ans,L+n->val+R);
  // Return to parent: can only go one direction
  return n->val+max(L,R);
}
// Call: dfs(root); return ans;
#8Coin ChangeMedium⏱ O(amount × coins)  |  🗄 O(amount)

Given coin denominations and a target amount, find minimum coins needed. Return -1 if impossible.

🧠 Key Insight: Bottom-up DP initializes with amount+1 (impossible sentinel). dp[i] = min coins to make amount i. Inner loop: try each coin, extend optimal solution for (i-coin).
🔴 Brute Force
// O(amount × coins^amount): brute force recursion
int solve(int rem){
  if(rem<0) return INT_MAX;
  if(rem==0) return 0;
  int best=INT_MAX;
  for(int c:coins)
    if(solve(rem-c)!=INT_MAX)
      best=min(best,1+solve(rem-c));
  return best;
}
🟡 Better
// O(amount × coins) with memo: top-down DP
vector<int> memo(amount+1,-1);
int solve(int rem){
  if(rem<0) return INT_MAX;
  if(rem==0) return 0;
  if(memo[rem]!=-1) return memo[rem];
  int best=INT_MAX;
  for(int c:coins)
    if(solve(rem-c)!=INT_MAX)
      best=min(best,1+solve(rem-c));
  return memo[rem]=best;
}
🟢 Optimal
// O(amount × coins) bottom-up DP
vector<int> dp(amount+1,amount+1);
dp[0]=0;
for(int i=1;i<=amount;++i)
  for(int c:coins)
    if(c<=i && dp[i-c]+1<dp[i])
      dp[i]=dp[i-c]+1;
return dp[amount]>amount?-1:dp[amount];
#9Word BreakMedium⏱ O(n^2 × m)  |  🗄 O(n)

Given string s and a word dictionary, can s be segmented into dictionary words?

🧠 Key Insight: dp[i] means 'can we form s[0..i-1] using dictionary words'. Only reachable positions (dp[j]=true) are meaningful starting points. Break early when dp[i] is set.
🔴 Brute Force
// Exponential: try all splits recursively
bool solve(int start){
  if(start==n) return true;
  for(int end=start+1;end<=n;++end)
    if(dict.count(s.substr(start,end-start)))
      if(solve(end)) return true;
  return false;
}
🟡 Better
// O(n^2) with memo
vector<int> memo(n+1,-1);
bool solve(int i){
  if(i==n) return true;
  if(memo[i]!=-1) return memo[i];
  for(int j=i+1;j<=n;++j)
    if(dict.count(s.substr(i,j-i))&&solve(j))
      return memo[i]=true;
  return memo[i]=false;
}
🟢 Optimal
// O(n^2) bottom-up: dp[i]=can reach position i
vector<bool> dp(n+1,false);
dp[0]=true;
for(int i=1;i<=n;++i)
  for(int j=0;j<i;++j)
    if(dp[j]&&dict.count(s.substr(j,i-j))){
      dp[i]=true;break;
    }
return dp[n];
#10Find Median from Data StreamHard⏱ O(log n) add, O(1) median  |  🗄 O(n)

Design a data structure that supports addNum(int) and findMedian() on a streaming input.

🧠 Key Insight: Two-heap invariant: maxH.size() == minH.size() OR maxH.size() == minH.size()+1. All elements in maxH <= all elements in minH. Median is either maxH.top() or average of both tops.
🔴 Brute Force
// O(n log n) per findMedian: sort the array
vector<int> data;
void add(int n){data.push_back(n);}
double median(){
  sort(data.begin(),data.end());
  int m=data.size();
  return m%2?data[m/2]:(data[m/2-1]+data[m/2])/2.0;
}
🟡 Better
// O(n) per add: insert in sorted position
void add(int n){
  auto it=lower_bound(data.begin(),data.end(),n);
  data.insert(it,n);
}
double median(){
  int m=data.size();
  return m%2?data[m/2]:(data[m/2-1]+data[m/2])/2.0;
}
🟢 Optimal
// O(log n) per add: two heaps maintaining the split
// maxH: lower half (max at top)
// minH: upper half (min at top)
void add(int n){
  maxH.push(n);                      // always add to lower first
  minH.push(maxH.top());maxH.pop(); // balance: largest lower goes to upper
  if(minH.size()>maxH.size()){       // keep sizes equal or lower has 1 extra
    maxH.push(minH.top());minH.pop();
  }
}
double median(){
  return maxH.size()>minH.size()?maxH.top():(maxH.top()+minH.top())/2.0;
}

Interview Q&A — Coding

❓ How do you identify a dynamic programming problem?
Two key properties: (1) Optimal substructure: optimal solution to the whole problem contains optimal solutions to subproblems. Example: minimum coins to make 11 = 1 + minimum coins to make 10. (2) Overlapping subproblems: same subproblems are solved repeatedly in naive recursion. Signs: the problem asks for minimum/maximum/count/feasibility of something. You can make a choice at each step and combine subproblem results. Classic categories: 1D DP (house robber, coin change, LIS), 2D DP (edit distance, LCS, knapsack), on strings, trees, graphs. How to solve: find the recurrence (how big problem depends on smaller problems), choose memo top-down or tabulation bottom-up, identify base cases.
Follow-up questions interviewers ask:
  • What is the difference between memoization and tabulation?
  • How do you optimize space in a 2D DP that only uses current and previous row?
  • When does greedy work instead of DP?
Common mistakes in answers:
  • Starting with code before identifying the recurrence — always write the recurrence as a comment first.
  • Confusing DP with divide-and-conquer — D&C subproblems are independent (merge sort); DP subproblems overlap.
❓ Walk me through your approach to a graph problem.
First: determine if it's directed or undirected, weighted or unweighted. Then choose algorithm: Shortest path unweighted → BFS (O(V+E)). Shortest path weighted non-negative → Dijkstra (O((V+E) log V) with heap). Shortest path with negative edges → Bellman-Ford (O(VE)). Topological order → Kahn's BFS or DFS. Connected components → Union-Find or DFS. Minimum spanning tree → Prim's or Kruskal's. All-pairs shortest path → Floyd-Warshall O(V^3). Implement: adjacency list for sparse graphs (most interview problems), adjacency matrix for dense/small. Common mistakes: not tracking visited set (infinite loop), off-by-one in BFS levels, forgetting to handle disconnected graphs.
