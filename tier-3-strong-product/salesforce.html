1 Spring Security — JWT authentication flow
spring-securityjwtoauth2
Hard 82%
JWT Flow
1. POST /login {username, password}
2. Server validates credentials
3. Server signs JWT: header.payload.signature (HMAC-SHA256 or RS256)
4. Client stores JWT (HttpOnly cookie or memory — NOT localStorage)
5. Client sends: Authorization: Bearer <token>
6. Server: JwtFilter extracts token → validate signature + expiry
          → set SecurityContextHolder with authentication
7. Request proceeds to controller
JWT Filter
@Component
class JwtAuthFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(HttpServletRequest req, ...) {
        String token = extractToken(req);
        if (token != null && jwtUtil.validate(token)) {
            UsernamePasswordAuthenticationToken auth =
                new UsernamePasswordAuthenticationToken(
                    jwtUtil.getUser(token), null,
                    jwtUtil.getAuthorities(token));
            SecurityContextHolder.getContext().setAuthentication(auth);
        }
        filterChain.doFilter(req, res);
    }
}
JWT vs Sessions
  • JWT: Stateless, scalable, no server-side storage. Con: can't invalidate before expiry.
  • Session: Server stores state, easy to invalidate. Con: sticky sessions or distributed session store needed.
Refresh Tokens
Short-lived access token (15min) + long-lived refresh token (7d) stored in HttpOnly cookie. Refresh endpoint issues new access token without re-login.
Follow-ups
• How do you implement token blacklisting for logout?
• What is the difference between OAuth2 and JWT?
• What are the security risks of storing JWT in localStorage?

4 Hibernate L1 and L2 cache — how they work
hibernatecachel1
Medium 76%
L1 Cache (Session Cache)
Default, always on. Scoped to a single Session (transaction). Within a session, the same entity loaded twice returns the same object (identity map). Cleared on session.close() or session.clear().
L2 Cache (Shared Cache)
Optional, cross-session. Shared across all sessions in a SessionFactory. Must be explicitly configured. Providers: Ehcache, Caffeine, Infinispan, Redis.
L2 Setup
# application.properties
spring.jpa.properties.hibernate.cache.use_second_level_cache=true
spring.jpa.properties.hibernate.cache.region.factory_class=\
    org.hibernate.cache.jcache.JCacheRegionFactory

# Entity
@Entity
@Cache(usage = CacheConcurrencyStrategy.READ_WRITE)
public class Product { ... }
Query Cache
Cache for JPQL/HQL query results. Must also have L2 enabled. Stores primary keys, not entities. Invalidated when any entity in result changes.
Cache Strategies
READ_ONLY, NONSTRICT_READ_WRITE, READ_WRITE, TRANSACTIONAL

5 Spring Boot auto-configuration internals deep dive
spring-bootauto-configconditional
Hard 76%
How it works
@SpringBootApplication includes @EnableAutoConfiguration.
Spring Boot reads META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports (or legacy spring.factories) to find all @AutoConfiguration classes.
Conditional Annotations
  • @ConditionalOnClass(DataSource.class) — only if DataSource on classpath
  • @ConditionalOnMissingBean — only if no user-defined bean of that type
  • @ConditionalOnProperty("spring.datasource.url") — only if property set
  • @ConditionalOnWebApplication — only in web context
Example: DataSource auto-config
@AutoConfiguration
@ConditionalOnClass(DataSource.class)
@ConditionalOnMissingBean(DataSource.class)
public class DataSourceAutoConfiguration {
    @Bean
    @ConditionalOnProperty("spring.datasource.url")
    public DataSource dataSource(DataSourceProperties props) {
        return props.initializeDataSourceBuilder().build();
    }
}
Debugging
--debug flag prints auto-config report: POSITIVE (matched) and NEGATIVE (not matched) conditions.
Follow-ups
• How do you exclude an auto-configuration?
• What is @ConfigurationProperties vs @Value?
• How does Spring Boot 3 change auto-configuration imports?

6 Spring WebFlux and Project Reactor — reactive programming
webfluxreactormono
Hard 74%
What is Reactive Programming
Non-blocking, event-driven programming with backpressure. Publisher emits data only as fast as subscriber can consume.
Project Reactor Types
  • Mono<T> — 0 or 1 element (like CompletableFuture)
  • Flux<T> — 0 to N elements (stream)
Example
// Blocking (Spring MVC)
@GetMapping("/user/{id}")
public User getUser(@PathVariable Long id) {
    return userService.findById(id);  // blocks thread!
}

// Reactive (Spring WebFlux)
@GetMapping("/user/{id}")
public Mono<User> getUser(@PathVariable Long id) {
    return userService.findById(id)  // non-blocking Mono
        .map(UserDto::from)
        .switchIfEmpty(Mono.error(new NotFoundException()));
}
When to use WebFlux
  • High-concurrency I/O bound workloads (thousands of concurrent connections)
  • Streaming data (SSE, WebSocket)
  • Avoid: CPU-bound work, blocking libraries (use bounded elastic scheduler)
Follow-ups
• What is the difference between publishOn and subscribeOn?
• How do you handle backpressure in Flux?
• When would you choose WebFlux over virtual threads (Java 21)?

1 Role-based (RBAC) vs Attribute-based (ABAC) access control
rbacabacauthorization
Medium 80%
RBAC — Role-Based Access Control
User → assigned Roles → Roles have Permissions

Roles: ADMIN, EDITOR, VIEWER, BILLING
Permissions: read:posts, write:posts, delete:posts, view:billing

User Alice: [EDITOR] → can read:posts + write:posts
User Bob:   [VIEWER] → can only read:posts

Simple, performant, easy to audit. Rigid: can't express context-based rules.
ABAC — Attribute-Based Access Control
Policy: user.department == resource.department AND resource.classification <= user.clearance

Request evaluated at runtime against policy engine (OPA — Open Policy Agent)

Attributes:
  Subject: {role, department, clearance, location}
  Resource: {classification, owner, department, sensitivity}
  Action: {read, write, delete}
  Environment: {time, IP, MFA_verified}

More expressive but complex. Used in enterprise, healthcare, government.
Implementation with OPA
# Rego policy (OPA):
allow { input.user.role == "admin" }
allow {
    input.action == "read"
    input.resource.owner == input.user.id
}
Follow-ups
• What is ReBAC (Relationship-Based Access Control) — Google Zanzibar?
• How do you implement row-level security in PostgreSQL?
• What is the principle of least privilege and how do you enforce it?
