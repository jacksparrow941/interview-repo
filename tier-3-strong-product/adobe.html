1 Two Sum
hash-maparrays
Easy 95%
Approach
Use a hash map to store complement = target - num as you iterate. If current number exists in map → found the pair.
Solution
def twoSum(nums, target):
    seen = {}
    for i, num in enumerate(nums):
        if num in seen:
            return [seen[num], i]
        seen[target - num] = i
Complexity
Time: O(n) | Space: O(n)
Follow-ups
• What if the array is sorted? (two pointers, O(1) space)
• What if we need ALL pairs? (collect instead of return first)
• 4-Sum approach?

2 Number of Islands
dfsbfsunion-find
Medium 92%
Approach
DFS or BFS. When land cell found, increment count and DFS to mark all connected land as visited.
Solution
def numIslands(grid):
    if not grid: return 0
    count = 0
    def dfs(r, c):
        if r < 0 or r >= len(grid) or c < 0 or c >= len(grid[0]): return
        if grid[r][c] != '1': return
        grid[r][c] = '0'  # mark visited
        for dr, dc in [(0,1),(0,-1),(1,0),(-1,0)]:
            dfs(r+dr, c+dc)
    for r in range(len(grid)):
        for c in range(len(grid[0])):
            if grid[r][c] == '1':
                count += 1; dfs(r, c)
    return count
Union-Find alternative
find with path compression + union by rank. O(α(n)) per operation. Good for streaming updates.
Complexity
Time: O(m×n) | Space: O(m×n) recursion stack
Follow-ups
• Max area of island? (count cells in each DFS)
• Number of distinct islands (accounting for shape)? (encode DFS path)
• Surrounded regions (capture)?

3 Longest Substring Without Repeating Chars
sliding-windowhash-set
Medium 88%
Approach
Sliding window with a set. Expand right pointer. If duplicate found, shrink left pointer until duplicate removed.
Solution
def lengthOfLongestSubstring(s):
    seen = {}; l = res = 0
    for r, c in enumerate(s):
        if c in seen and seen[c] >= l:
            l = seen[c] + 1
        seen[c] = r
        res = max(res, r - l + 1)
    return res
Complexity
Time: O(n) | Space: O(min(m,n)) where m = charset size
Follow-ups
• At most 2 distinct characters? (sliding window with count map)
• At most k distinct characters? (generalize with deque or count map)

4 Maximum Subarray (Kadane's Algorithm)
dpkadane
Medium 82%
Kadane's Algorithm
Track current subarray sum. If it goes negative, reset to 0 (start fresh). Track global maximum throughout.
Solution
def maxSubArray(nums):
    cur = best = nums[0]
    for n in nums[1:]:
        cur = max(n, cur + n)
        best = max(best, cur)
    return best
Complexity
Time: O(n) | Space: O(1)
Extension
For indices: track start/end/temp_start. For 2D: apply Kadane on column sums for each row pair.
Follow-ups
• What if we need the actual subarray (not just the sum)?
• Maximum product subarray — how is it different? (track both min and max because negatives)

5 Best Time to Buy and Sell Stock
greedy
Easy 82%
Approach
One pass. Track running minimum price. At each step, compute profit = price - min_price. Track max profit.
Solution
def maxProfit(prices):
    min_p, profit = float('inf'), 0
    for p in prices:
        min_p = min(min_p, p)
        profit = max(profit, p - min_p)
    return profit
Complexity
Time: O(n) | Space: O(1)
Follow-ups

• Stock with cooldown? (DP with states)

6 Valid Parentheses
stack
Easy 82%
Approach
Use a stack. Push open brackets. When closing bracket found, check if top of stack is matching open.
Solution
def isValid(s):
    stack = []
    match = {')':'(', ']':'[', '}':'{'}
    for c in s:
        if c in match:
            if not stack or stack[-1] != match[c]: return False
            stack.pop()
        else: stack.append(c)
    return not stack
Complexity
Time: O(n) | Space: O(n)
Follow-ups

• Minimum additions to make string valid? (unmatched opens + unmatched closes)

7 Binary Tree Level Order Traversal
bfsqueue
Medium 82%
Approach
BFS with queue. Process all nodes at current level before moving to next. Use level size or sentinel None to track level boundaries.
Solution
from collections import deque
def levelOrder(root):
    if not root: return []
    res, q = [], deque([root])
    while q:
        level = []
        for _ in range(len(q)):
            node = q.popleft()
            level.append(node.val)
            if node.left: q.append(node.left)
            if node.right: q.append(node.right)
        res.append(level)
    return res
Complexity
Time: O(n) | Space: O(w) where w = max width
Follow-ups
• Zigzag level order? (alternate direction each level)
• Right side view? (take last element of each level)
• Average of each level?

8 Merge Intervals
sortingintervals
Medium 79%
Approach
Sort by start time. Merge if next interval starts ≤ current end. Extend current end to max of both.
Solution
def merge(intervals):
    intervals.sort(key=lambda x: x[0])
    res = [intervals[0]]
    for s, e in intervals[1:]:
        if s <= res[-1][1]: res[-1][1] = max(res[-1][1], e)
        else: res.append([s, e])
    return res
Complexity
Time: O(n log n) | Space: O(n)
Follow-ups
• Insert interval into sorted list of non-overlapping intervals?
• Meeting rooms — is there any conflict? (sort + check adjacent)
• Minimum meeting rooms needed? (heap tracking end times)

1 Docker container vs Virtual Machine — key differences?
dockervmcontainer
Easy 93%
Answer
Virtual Machine: Full OS per VM, hardware emulation via hypervisor (Type-1: bare metal, Type-2: hosted). Heavy: ~GBs, slow boot (~minutes), strong isolation.
Docker Container: Shares host OS kernel, isolates via Linux namespaces (PID, NET, MNT, UTS, IPC) + cgroups for resource limits. Lightweight: ~MBs, starts in milliseconds, process-level isolation.
Key Differences
  • Boot time: VM ~1-2 min | Container ~100ms
  • Size: VM ~GBs | Container ~MBs (shared layers)
  • Isolation: VM = full kernel isolation | Container = namespace isolation (kernel shared)
  • Use case: VM for multi-OS, strong isolation | Container for microservices, CI/CD
Follow-ups
• What Linux namespaces does Docker use? (PID, NET, MNT, IPC, UTS, USER)
• How do cgroups limit CPU/memory in containers?
• What is a container runtime? (runc, containerd, CRI-O)

2 How do Docker image layers work? (Union filesystem)
dockerlayersoverlay2
Medium 90%
Answer
Docker images are built as read-only layers stacked using a Union Filesystem (OverlayFS/AUFS). Each RUN, COPY, ADD instruction in a Dockerfile creates a new layer.

When a container runs, Docker adds a thin read-write layer on top (Copy-on-Write). Writes go to the container layer; reads search layers bottom-up.
Dockerfile Layer Example
FROM ubuntu:22.04          # Layer 1: base OS
RUN apt-get install -y java # Layer 2: java install
COPY app.jar /app/          # Layer 3: app binary
CMD ["java", "-jar", "/app/app.jar"]  # metadata only
Optimization Tips
  • Order layers from least to most frequently changing
  • Combine RUN commands to reduce layer count
  • Use .dockerignore to exclude build artifacts
  • Use multi-stage builds to discard build-time layers
Follow-ups
• What is docker build --cache-from?
• How does docker squash work?
• Difference between image and container filesystem?

4 ConfigMaps vs Secrets in Kubernetes
kubernetesconfigmapsecrets
Easy 88%
ConfigMap
Stores non-sensitive configuration as key-value pairs. Mounted as environment variables or volume files. Plain text in etcd.
Secret
Stores sensitive data (passwords, tokens, TLS certs). Base64-encoded in etcd (NOT encrypted by default). Enable encryption at rest with EncryptionConfiguration. Types: Opaque, kubernetes.io/tls, kubernetes.io/dockerconfigjson, etc.
Usage
# Mount as env
env:
- name: DB_PASSWORD
  valueFrom:
    secretKeyRef:
      name: db-secret
      key: password

# Mount as volume
volumeMounts:
- name: config
  mountPath: /etc/config
volumes:
- name: config
  configMap:
    name: app-config
Best Practices
  • Use external secret managers: HashiCorp Vault, AWS Secrets Manager with External Secrets Operator
  • Never bake secrets into Docker images
  • RBAC: restrict Secret read access to specific ServiceAccounts
Follow-ups

• What is Sealed Secrets (Bitnami)?

5 Git internals — rebase vs merge, when to use each
gitrebasemerge
Medium 88%
Merge
Creates a merge commit that ties two branches together. Preserves full history including branch structure. Safe for shared branches — never rewrites history.
git checkout main
git merge feature/login
# Creates commit: Merge branch 'feature/login'
Rebase
Replays commits from one branch onto another. Creates linear history. Rewrites commit SHAs — never rebase shared/public branches.
git checkout feature/login
git rebase main
# Moves feature commits on top of latest main
When to use
  • Merge: Merging feature into main (preserves context). Shared branches.
  • Rebase: Keeping feature branch up-to-date with main. Clean PR history. git pull --rebase.
  • Squash merge: Combine all feature commits into 1 clean commit on main.
Interactive Rebase
git rebase -i HEAD~3
# Options: pick, squash, fixup, reword, drop
Follow-ups
• What is git cherry-pick?
• How do you recover from a bad rebase? (git reflog)
• What is the difference between git reset and git revert?

Jenkins

  • Cons: maintenance overhead, not cloud-native

  • Runners: shared or self-hosted
  • Best for teams already on GitLab
When to choose
  • GitHub Actions: GitHub-hosted projects, modern cloud-native teams
  • Jenkins: Legacy enterprise, complex custom pipelines
  • GitLab CI: GitLab monorepo, all-in-one DevSecOps

2 Design an Elevator System
design-patternsscheduler
Medium 85%
Scheduling Strategies
  • SCAN (Elevator algorithm): Go in one direction, serve all requests, reverse. Minimizes total travel.
  • LOOK: Like SCAN but reverses when no more requests in current direction (doesn't go to end).
  • FCFS: First come first served. Simple but suboptimal.
Design
class Elevator {
    int currentFloor; Direction dir; ElevatorState state;
    List<Request> queue;  // sorted by floor
    void addRequest(Request r) { queue.add(r); processNext(); }
    void processNext() {
        Request next = schedulingStrategy.pickNext(queue, currentFloor, dir);
        moveTo(next.floor);
    }
}
class ElevatorSystem {
    List<Elevator> elevators;
    void requestElevator(int floor, Direction d) {
        Elevator best = findOptimalElevator(floor, d);  // least-travel heuristic
        best.addRequest(new Request(floor, d));
    }
}
