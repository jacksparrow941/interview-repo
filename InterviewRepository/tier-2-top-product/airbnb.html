1 Three Sum
two-pointerssorting
Medium 85%
Approach
Sort array. For each element, use two pointers on the rest to find pairs summing to -nums[i]. Skip duplicates at each level.
Solution
def threeSum(nums):
    nums.sort(); res = []
    for i in range(len(nums)-2):
        if i > 0 and nums[i] == nums[i-1]: continue
        l, r = i+1, len(nums)-1
        while l < r:
            s = nums[i]+nums[l]+nums[r]
            if s == 0: res.append([nums[i],nums[l],nums[r]]); l+=1; r-=1
            while l < r and nums[l]==nums[l-1]: l+=1
            while l < r and nums[r]==nums[r+1]: r-=1
            elif s < 0: l+=1
            else: r-=1
    return res
Complexity
Time: O(n²) | Space: O(1) excluding output
Follow-ups
• How does 4-Sum extend this? (add outer loop, O(n³))
• What is the hash-map approach and why is two-pointer preferred?

2 Course Schedule (Cycle Detection)
topological-sortdfs
Medium 82%
Approach
DFS with 3-color marking: WHITE(0)=unvisited, GRAY(1)=in-current-path, BLACK(2)=done. Cycle detected if GRAY node encountered again.
Solution
def canFinish(numCourses, prerequisites):
    graph = [[] for _ in range(numCourses)]
    for a, b in prerequisites: graph[b].append(a)
    color = [0] * numCourses
    def dfs(v):
        if color[v] == 1: return False  # cycle
        if color[v] == 2: return True
        color[v] = 1
        if not all(dfs(u) for u in graph[v]): return False
        color[v] = 2; return True
    return all(dfs(v) for v in range(numCourses))
Complexity
Time: O(V+E) | Space: O(V+E)
Follow-ups
• Return actual order (Course Schedule II)? Kahn's BFS topo sort.
• Detect cycle in undirected graph? (parent tracking instead of 3-color)

3 Meeting Rooms II
heapgreedyintervals
Medium 82%
Approach
DP with memoization. dp[i][j] = LCS length of s1[i:] and s2[j:]. If chars match: 1 + dp[i+1][j+1]. Else max(dp[i+1][j], dp[i][j+1]).
Solution
def longestCommonSubsequence(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(m-1,-1,-1):
        for j in range(n-1,-1,-1):
            if text1[i]==text2[j]:
                dp[i][j] = 1 + dp[i+1][j+1]
            else:
                dp[i][j] = max(dp[i+1][j], dp[i][j+1])
    return dp[0][0]
Complexity
Time: O(m×n) | Space: O(m×n), optimizable to O(min(m,n))
Follow-ups
• Shortest common supersequence? (m+n - LCS)
• Edit distance (Levenshtein)? (similar DP with insert/delete/replace)
• LCS of 3 strings?

4 Product of Array Except Self
prefix-suffix
Medium 80%
Approach
Prefix product from left, then multiply with suffix product from right in one pass. No division needed.
Solution
def productExceptSelf(nums):
    n = len(nums); res = [1]*n
    # Left pass
    prefix = 1
    for i in range(n):
        res[i] = prefix; prefix *= nums[i]
    # Right pass
    suffix = 1
    for i in range(n-1,-1,-1):
        res[i] *= suffix; suffix *= nums[i]
    return res
Complexity
Time: O(n) | Space: O(1) (output array not counted)
Follow-ups
• What if zeros are in the array?
• Can you solve with division in O(n) but handle zeros? (count zeros separately)

5 Merge Intervals
sortingintervals
Medium 79%
Approach
Sort by start time. Merge if next interval starts ≤ current end. Extend current end to max of both.
Solution
def merge(intervals):
    intervals.sort(key=lambda x: x[0])
    res = [intervals[0]]
    for s, e in intervals[1:]:
        if s <= res[-1][1]: res[-1][1] = max(res[-1][1], e)
        else: res.append([s, e])
    return res
Complexity
Time: O(n log n) | Space: O(n)
Follow-ups
• Insert interval into sorted list of non-overlapping intervals?
• Meeting rooms — is there any conflict? (sort + check adjacent)
• Minimum meeting rooms needed? (heap tracking end times)

1 Design Twitter/Feed System
fanoutpush-pullredis-sorted-set
Hard 88%
Design a Scalable Key-Value Store
Like DynamoDB/Redis Cluster. Key decisions: partitioning, replication, consistency.
Architecture
  • Consistent hashing ring with virtual nodes for partitioning
  • Replication: N=3. Coordinator writes to 3 nodes.
  • Quorum: W=2, R=2. W+R>N → strong consistency. W=1,R=1 → eventual.
  • Storage engine: LSM-tree (RocksDB) for write optimization
  • Gossip protocol for cluster membership/failure detection
Data Flow
PUT key=A value=X:
  1. Client → any node (coordinator)
  2. Hash(A) → ring position → 3 responsible nodes
  3. Coordinator writes to all 3, waits for W=2 acks
  4. Returns success

GET key=A:
  1. Coordinator queries R=2 nodes
  2. Returns latest version (by timestamp or vector clock)
  3. Read repair: update stale replica asynchronously
Follow-ups
• How does hinted handoff handle temporarily unavailable nodes?
• What is sloppy quorum vs strict quorum?
• How do you handle hot keys? (request sharding, local cache)

1 Design an A/B testing platform
ab-testingexperimentationstatistics
Hard 85%
Core Components
Experiment Config Service → stores experiment definition
  (variants, allocation %, targeting rules, metrics)

Assignment Service → deterministic bucketing by user_id
  hash(user_id + experiment_id) % 100 < allocation%
  → same user always in same bucket (sticky assignment)
  → results cached in Redis

Event Tracking → user actions logged with experiment_id + variant
  → Kafka → Data Warehouse (Clickhouse/BigQuery)

Analysis Service → daily/real-time stats computation
  → t-test / z-test for significance
  → dashboard with p-value, confidence interval, lift %
Statistical Concepts
  • p-value < 0.05: Less than 5% chance result is due to random variation
  • Statistical power: Probability of detecting a real effect. Usually target 80%.
  • MDE (Minimum Detectable Effect): Smallest effect worth detecting → determines sample size
  • Sample size calculator: n = 16σ²/δ² (for 80% power, 5% significance)
  • Multiple testing problem: 20 experiments at 5% significance → 1 false positive on average. Fix: Bonferroni correction or FDR.
Common Pitfalls
  • Novelty effect: New feature gets engagement just because it's new — run longer
  • Network effect: Treating control and treatment users who interact with each other — cluster randomization
  • Peeking: Stopping early when p < 0.05 inflates false positive rate — use sequential testing
Follow-ups
• What is a holdout group and why is it important?
• How do you handle metric tradeoffs? (CTR increases but conversion decreases)
• What is Bayesian A/B testing and how does it differ from frequentist?

2 Design a search ranking system
search-rankingelasticsearchlearning-to-rank
Hard 85%
Search Stack
User Query
    ↓
Query Understanding: spell check, tokenization, synonym expansion, intent classification
    ↓
Retrieval (Elasticsearch / Lucene):
  BM25 score: TF-IDF with length normalization
  → top-1000 candidates in <50ms
    ↓
Learning-to-Rank (LTR) Model:
  Features: BM25 score, query-doc semantic similarity,
            user click history, item popularity, freshness, location
  Model: LightGBM / BERT cross-encoder
  → rerank top-1000 to top-10
    ↓
Business Rules: boost paid listings, filter unavailable items
    ↓ 
Response
Elasticsearch Internals
  • Inverted index: term → [doc_id, positions]. Builds at index time.
  • Sharding: index split into shards. Search parallelized across shards.
  • Analyzers: tokenizer + filters (lowercase, stemming, stopwords) at index + query time
  • Boosting: title^3 body^1 — title matches worth 3x body matches
Learning-to-Rank
  • Pointwise: Independent regression/classification per document
  • Pairwise (RankNet): Prefer doc A over B → binary classification
  • Listwise (LambdaMART): Optimize NDCG directly. Best quality.
Follow-ups
• How do you handle cold-start for new items with no click data?
• What is NDCG (Normalized Discounted Cumulative Gain) and how do you compute it?
• How does Airbnb use neural network for search ranking? (listing embeddings)
