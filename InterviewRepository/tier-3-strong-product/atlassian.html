1 Binary Tree Level Order Traversal
bfsqueue
Medium 82%
Approach
BFS with queue. Process all nodes at current level before moving to next. Use level size or sentinel None to track level boundaries.
Solution
from collections import deque
def levelOrder(root):
    if not root: return []
    res, q = [], deque([root])
    while q:
        level = []
        for _ in range(len(q)):
            node = q.popleft()
            level.append(node.val)
            if node.left: q.append(node.left)
            if node.right: q.append(node.right)
        res.append(level)
    return res
Complexity
Time: O(n) | Space: O(w) where w = max width
Follow-ups
• Zigzag level order? (alternate direction each level)
• Right side view? (take last element of each level)
• Average of each level?

2 Course Schedule (Cycle Detection)
topological-sortdfs
Medium 82%
Approach
DFS with 3-color marking: WHITE(0)=unvisited, GRAY(1)=in-current-path, BLACK(2)=done. Cycle detected if GRAY node encountered again.
Solution
def canFinish(numCourses, prerequisites):
    graph = [[] for _ in range(numCourses)]
    for a, b in prerequisites: graph[b].append(a)
    color = [0] * numCourses
    def dfs(v):
        if color[v] == 1: return False  # cycle
        if color[v] == 2: return True
        color[v] = 1
        if not all(dfs(u) for u in graph[v]): return False
        color[v] = 2; return True
    return all(dfs(v) for v in range(numCourses))
Complexity
Time: O(V+E) | Space: O(V+E)

• Detect cycle in undirected graph? (parent tracking instead of 3-color)

3 Product of Array Except Self
prefix-suffix
Medium 80%
Approach
Prefix product from left, then multiply with suffix product from right in one pass. No division needed.
Solution
def productExceptSelf(nums):
    n = len(nums); res = [1]*n
    # Left pass
    prefix = 1
    for i in range(n):
        res[i] = prefix; prefix *= nums[i]
    # Right pass
    suffix = 1
    for i in range(n-1,-1,-1):
        res[i] *= suffix; suffix *= nums[i]
    return res
Complexity
Time: O(n) | Space: O(1) (output array not counted)
Follow-ups
• What if zeros are in the array?
• Can you solve with division in O(n) but handle zeros? (count zeros separately)

5 Merge Intervals
sortingintervals
Medium 79%
Approach
Sort by start time. Merge if next interval starts ≤ current end. Extend current end to max of both.
Solution
def merge(intervals):
    intervals.sort(key=lambda x: x[0])
    res = [intervals[0]]
    for s, e in intervals[1:]:
        if s <= res[-1][1]: res[-1][1] = max(res[-1][1], e)
        else: res.append([s, e])
    return res
Complexity
Time: O(n log n) | Space: O(n)

6 Group Anagrams
hash-mapsorting
Medium 78%
Approach
Group strings by sorted-character key. Anagrams share the same sorted string.
Solution
from collections import defaultdict
def groupAnagrams(strs):
    groups = defaultdict(list)
    for s in strs:
        groups[tuple(sorted(s))].append(s)
    return list(groups.values())
Optimization
Use tuple of 26-char counts as key instead of sorting: O(n) per string instead of O(k log k).
Complexity

1 Docker container vs Virtual Machine — key differences?
dockervmcontainer
Easy 93%
Answer
Virtual Machine: Full OS per VM, hardware emulation via hypervisor (Type-1: bare metal, Type-2: hosted). Heavy: ~GBs, slow boot (~minutes), strong isolation.
Docker Container: Shares host OS kernel, isolates via Linux namespaces (PID, NET, MNT, UTS, IPC) + cgroups for resource limits. Lightweight: ~MBs, starts in milliseconds, process-level isolation.
Key Differences
  • Boot time: VM ~1-2 min | Container ~100ms
  • Size: VM ~GBs | Container ~MBs (shared layers)
  • Isolation: VM = full kernel isolation | Container = namespace isolation (kernel shared)
  • Use case: VM for multi-OS, strong isolation | Container for microservices, CI/CD
Follow-ups
• What Linux namespaces does Docker use? (PID, NET, MNT, IPC, UTS, USER)
• How do cgroups limit CPU/memory in containers?
• What is a container runtime? (runc, containerd, CRI-O)

2 Kubernetes architecture — explain all components
kubernetesapi-serveretcd
Hard 92%
Control Plane
  • kube-apiserver: REST API gateway; all kubectl commands go here. Validates, authenticates, stores to etcd.
  • etcd: Distributed KV store (Raft consensus). Single source of truth for all cluster state.
  • kube-scheduler: Watches unscheduled pods, assigns them to nodes based on resources, affinity, taints.
  • kube-controller-manager: Runs controllers (ReplicaSet, Node, Job, Endpoint) in reconciliation loops.
  • cloud-controller-manager: Integrates with cloud provider APIs (LB, volumes, routes).
Worker Nodes
  • kubelet: Agent on each node. Ensures containers in pods are running. Reports to API server.
  • kube-proxy: Manages iptables/IPVS rules for Service networking and load balancing.
  • Container Runtime: containerd or CRI-O. Pulls images, runs containers.
Flow: kubectl apply
kubectl apply → apiserver (auth+validate) → etcd (store)
→ controller-manager (create pods) → scheduler (assign node)
→ kubelet on node (pull image, start container)
Follow-ups
• What happens when the API server goes down?
• How does etcd leader election work?
• Difference between kubelet and kube-proxy?

3 How do Docker image layers work? (Union filesystem)
dockerlayersoverlay2
Medium 90%
Answer
Docker images are built as read-only layers stacked using a Union Filesystem (OverlayFS/AUFS). Each RUN, COPY, ADD instruction in a Dockerfile creates a new layer.

When a container runs, Docker adds a thin read-write layer on top (Copy-on-Write). Writes go to the container layer; reads search layers bottom-up.
Dockerfile Layer Example
FROM ubuntu:22.04          # Layer 1: base OS
RUN apt-get install -y java # Layer 2: java install
COPY app.jar /app/          # Layer 3: app binary
CMD ["java", "-jar", "/app/app.jar"]  # metadata only
Optimization Tips
  • Order layers from least to most frequently changing
  • Combine RUN commands to reduce layer count
  • Use .dockerignore to exclude build artifacts
  • Use multi-stage builds to discard build-time layers
Follow-ups
• What is docker build --cache-from?
• How does docker squash work?
• Difference between image and container filesystem?

4 Pod vs ReplicaSet vs Deployment vs StatefulSet
kubernetespoddeployment
Medium 90%
Pod
Smallest deployable unit. 1+ containers sharing network namespace and volumes. Ephemeral — deleted pods don't restart.
ReplicaSet
Ensures N pod replicas are always running. Uses label selectors. Rarely used directly — Deployments manage them.
Deployment
Manages ReplicaSets for stateless apps. Provides: rolling updates, rollback, pause/resume. kubectl rollout undo deployment/app for rollback.
StatefulSet
For stateful apps (databases, Kafka, ZooKeeper). Provides: stable pod names (pod-0, pod-1), stable DNS, ordered start/stop, per-pod PersistentVolumeClaims.
When to use what
  • Stateless API service → Deployment
  • Database (MySQL, Redis) → StatefulSet
  • One pod per node → DaemonSet
  • One-off batch job → Job/CronJob

6 ConfigMaps vs Secrets in Kubernetes
kubernetesconfigmapsecrets
Easy 88%
ConfigMap
Stores non-sensitive configuration as key-value pairs. Mounted as environment variables or volume files. Plain text in etcd.
Secret
Stores sensitive data (passwords, tokens, TLS certs). Base64-encoded in etcd (NOT encrypted by default). Enable encryption at rest with EncryptionConfiguration. Types: Opaque, kubernetes.io/tls, kubernetes.io/dockerconfigjson, etc.
Usage

      name: db-secret

# Mount as volume

- name: config
  mountPath: /etc/config
volumes:
- name: config
  configMap:
    name: app-config
Best Practices
  • Use external secret managers: HashiCorp Vault, AWS Secrets Manager with External Secrets Operator
  • Never bake secrets into Docker images
  • RBAC: restrict Secret read access to specific ServiceAccounts

7 Git internals — rebase vs merge, when to use each
gitrebasemerge
Medium 88%
Merge
Creates a merge commit that ties two branches together. Preserves full history including branch structure. Safe for shared branches — never rewrites history.
git checkout main
git merge feature/login
# Creates commit: Merge branch 'feature/login'
Rebase
Replays commits from one branch onto another. Creates linear history. Rewrites commit SHAs — never rebase shared/public branches.
git checkout feature/login
git rebase main
# Moves feature commits on top of latest main
When to use
  • Merge: Merging feature into main (preserves context). Shared branches.
  • Rebase: Keeping feature branch up-to-date with main. Clean PR history. git pull --rebase.
  • Squash merge: Combine all feature commits into 1 clean commit on main.
Interactive Rebase
git rebase -i HEAD~3
# Options: pick, squash, fixup, reword, drop

8 What is Helm and what problem does it solve?
helmchartrelease
Medium 86%
What is Helm
Helm is the package manager for Kubernetes. It bundles K8s manifests into a Chart (a directory of YAML templates + values.yaml). Manages versioned releases, upgrades, and rollbacks.
Key Concepts
  • Chart: Package of K8s manifests (Deployment, Service, Ingress, etc.)
  • Release: A running instance of a chart in a cluster
  • Values: Configuration injected into templates at render time
  • Repository: Collection of charts (like npm/pip registry)
Common Commands
helm install myapp ./chart -f values.prod.yaml
helm upgrade myapp ./chart --set image.tag=v2.0
helm rollback myapp 1
helm template ./chart  # render YAML without installing
Helm vs Kustomize
  • Helm: Templating + packaging + release management. Better for distributing software.
  • Kustomize: Overlay-based patching, no templating. Better for environment-specific customization.

Table-Driven Tests
func TestAdd(t *testing.T) {
    tests := []struct {
        name string; a, b, want int
    }{
        {"positive", 2, 3, 5},
        {"negative", -1, 1, 0},
        {"zeros", 0, 0, 0},
    }
    for _, tc := range tests {
        t.Run(tc.name, func(t *testing.T) {
            if got := Add(tc.a, tc.b); got != tc.want {
                t.Errorf("Add(%d,%d)=%d, want %d", tc.a, tc.b, got, tc.want)
            }
        })
    }
}
